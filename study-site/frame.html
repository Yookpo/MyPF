2 · 시간축

    Frame Analysis

    이 페이지의 질문 Run 루프 한 바퀴 동안 어떤 함수가 어떤 순서로 불리고, DrawIndexed가 호출되는 순간 파이프라인에는 무엇이 준비되어 있는가?

    학습 목표

    이 페이지를 마치면 다음을 할 수 있다.

    1. 한 프레임의 시작부터 Present까지 호출 순서를 빈 종이에 재구성한다
    2. 각 단계가 CPU 작업인지, GPU에 명령을 남기는지 구분한다
    3. DrawIndexed 직전 파이프라인의 모든 슬롯에 무엇이 걸려 있고, 그것이 언제 · 어디서 걸렸는지 말한다
    4. 한 텍스처가 한 프레임 안에서 출력(RTV)과 입력(SRV)을 오가는 순서를 설명한다
    5. 상태 기계라서 생기는 일 — 앞 패스가 남긴 상태, ImGui의 백업·복원 — 을 설명한다

    프레임 지도

    한 프레임은 여섯 묶음, 23단계로 나뉜다. 묶음을 누르면 타임라인의 그 위치로 이동한다.

    1. A프레임 시작01–04
    2. BUpdate05–06
    3. C프레임 준비07–09
    4. D씬 패스 ×810–15
    5. E후처리16–20
    6. FUI · Present21–23

    CPU와 GPU는 같은 시간에 일하지 않는다

    DX11의 Context->… 호출은 CPU에서 곧바로 반환된다. 드라이버가 명령을 버퍼에 쌓아 두고, GPU는 그것을 나중에 실행한다. 그래서 각 단계의 GPU 칸은 "이 명령이 GPU에서 실행될 때 일어나는 일"이다. 실제 실행 시점은 드라이버가 정하며 Present 뒤일 수도 있다.

    정답과 근거

    파이프라인은 상태 기계라서, 20단계 톤 매핑 패스가 건 백버퍼 RTV(Renderer.cpp:541 → :403)가 그대로 남아 있다. ImGui는 지금 걸린 출력에 그린다. 톤 매핑과 ImGui 사이에 다른 패스를 끼워 넣으면 UI가 엉뚱한 타깃에 그려질 수 있다.

    Object CB 하나를 한 프레임에 8번 Map(WRITE_DISCARD)한다. 앞 Draw가 GPU에서 아직 실행되지 않았다면, 그 Draw는 어떤 world 행렬을 보게 되는가?

    정답과 근거

    자기 world 행렬을 본다. WRITE_DISCARD는 "이전 내용은 버려도 된다"는 약속이라, 드라이버가 새 메모리를 내주고 이전 메모리는 그것을 쓰는 명령이 끝날 때까지 보존한다(버퍼 리네이밍). 그래서 같은 상수 버퍼를 Draw마다 덮어써도 된다(D3D11Utils.cpp:304).

    후처리 패스(17~20)가 실행될 때 IA의 VB 슬롯에는 무엇이 걸려 있고, 왜 문제가 되지 않는가?

    정답과 근거

    마지막 씬 Draw의 greybox VB가 남아 있다. DrawFullScreenPass는 InputLayout만 null로 바꾸고 VB는 건드리지 않는다(Renderer.cpp:408). 전체 화면 VS는 SV_VertexID만 쓰므로 정점 버퍼를 읽지 않는다(fullscreenVertexShader.hlsl:10).

    Play HUD의 [E] Interact는 스위치를 바라본 프레임보다 한 프레임 늦게 뜬다. 타임라인의 어느 두 단계 때문인가?

    정답과 근거

    03(UI 기록)이 06(상호작용 판정)보다 먼저 실행된다. HUD는 이전 프레임의 IsHighlighted를 읽는다. 반면 Rim 강조는 06에서 Material을 바꾸고 같은 프레임의 11이 읽으므로 지연이 없다.

    E 키를 계속 누르고 있으면 스위치가 매 프레임 토글되는가?

    정답과 근거

    아니다. pressed는 키가 떼어진 상태에서 눌린 상태로 바뀔 때만 켜지고(InputSystem.cpp:19-22), 23단계 EndFrame에서 꺼진다. 키 반복 메시지는 이미 m_keyDown이 참이라 다시 켜지 않는다.

    실험 실행해서 확인할 것

    RenderDoc에서 8번째 씬 DrawIndexed를 선택하고 Pipeline State 탭을 위 "DrawIndexed 직전 상태"와 슬롯 단위로 대조하라.

    확인 포인트

    PS b0이 Light CB인지, Blend State가 비어 있는지(기본값), OM에 HDR 타깃과 깊이 버퍼가 함께 걸려 있는지 본다.

    Event Browser에서 이벤트 순서를 이 타임라인과 대조하라. Clear 2개, 씬 DrawIndexed 8개, Draw 12개, ImGui DrawIndexed, Present를 찾아라.

    확인 포인트

    Clear 두 개는 HDR 타깃과 DSV다(Renderer.cpp:322-323). 백버퍼 Clear는 없다 — 톤 매핑 패스가 화면 전체를 덮어쓰기 때문이다.
